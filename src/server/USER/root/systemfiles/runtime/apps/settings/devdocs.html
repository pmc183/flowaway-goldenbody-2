App Developer Guide

This guide assumes the runtime already creates the app folder and installs the files for you. During development, use the existing apps under /systemfiles/runtime/apps as working examples.

Start with a small app

1. Choose the app model

Normal app is the safest default. Admin app has direct runtime access and requires matching API keys. Headless hides an app from the start menu, taskbar, and Alt+Tab menu.

2. Create the package files

Put entry.json, one executable entry file, and every icon/script/asset the app needs in one source folder.

3. Define behavior

Use window.__goldenbodyAPI for a normal app, window.protectedGlobals for a verified admin app, or self.api for a terminal worker.

4. Package and install

Make a ZIP with your app folder, open App Installer, and install the ZIP.

Recommended first package

hello-app.zip
└── hello-app/
    ├── entry.json
    ├── script.js
    └── icon.txt

The ZIP must contain exactly one top-level app folder. All app files, including entry.json, must be inside that folder.

Minimal normal-app entry

{
  "id": "helloApp",
  "label": "Hello App",
  "jsFile": "script.js",
  "iconFile": "icon.txt",
  "pngEnabled": false,
  "requestAdminPerm": false,
  "openfileCapability": [],
  "headless": false
}

Minimal normal-app script


document.body.innerHTML = `<main style="padding: 16px">
  <h2>Hello App</h2>
  <p>Your app is running.</p>
</main>`;

Before shipping

  • Keep all package paths relative to entry.json.
  • Use a unique, stable id. The id becomes the package folder name after sanitization.
  • Test with requestAdminPerm: false first.
  • Include an icon for apps that appear in the interface.

entry.json

entry.json is the package and launch manifest. It must be located at /yourapp/entry.json.

Common fields

  • id — (Required) unique package/app identifier.
  • jsFile — (Required) executable file path relative to the app folder.
  • label — (Potentially required) display name; required unless headless is true.
  • iconFile — (Potentially required) icon path relative to the app folder; required unless headless is true.
  • pngEnabled — (Potentially required) render iconFile as a PNG. The icon can instead be text if this is set to false.
  • requestAdminPerm — (Required) true for direct runtime access, false for a normal app. The js API key must be inside this app folder otherwise the app will not be able to be parsed.
  • openfileCapability — (Optional) extensions or patterns that File Explorer uses for “Open with,” for example [".txt", ".md"]; "*" means all files.
  • enableDebugging — (Optional) enables devtools inside the app, useful when your device does not support native devtools.
  • headless — (Optional) hide the app from the start menu, taskbar, and Alt+Tab menu. It does not remove the app window, instead you need to put { minimize: true } in the startupPos if you want to hide the window. (see below)
  • startupPos — (Optional) initial window position and size; supports x, y, width, height, maximize, and minimize.
  • hiddenDragstrip — (Optional) hide the iframe drag/resize strip.
  • hiddenTitlebar — (Optional) hide the iframe titlebar.
  • createShortcutUponInstallation — (Optional) create a desktop shortcut after installation.

Complete normal-app entry

{
  "id": "notesApp",
  "label": "Notes",
  "jsFile": "script.js",
  "iconFile": "icon.txt",
  "pngEnabled": false,
  "requestAdminPerm": false,
  "openfileCapability": [".txt", ".md"],
  "enableDebugging": true,
  "hiddenTitlebar": false,
  "hiddenDragstrip": false,
  "createShortcutUponInstallation": true,
  "startupPos": { "x": 120, "y": 80, "width": 760, "height": 500 },
  "headless": false
}

Admin-only fields

  • functionName — global launcher function name.
  • globalVarObjectString — global object holding app state.
  • allAppArrayString — property on that object tracking app instances.
  • cmf and cmfl1 — app context-menu hooks.

Command fields

Use cmd or commands; commands take precedence if both exist. Command names are normalized to lowercase letters only: the runtime lowercases names and removes spaces, numbers, and symbols, then drops names that become empty.

"cmd": [
  { "name": "backup", "src": "workers/backup.js", "receive_onkill_handler": true },
  { "name": "cleanCache", "src": "workers/clean.js" }
]

For example, cleanCache becomes cleancache, and Backup 2! becomes backup.

Normal apps

Set requestAdminPerm to false for normal apps.

Launch arguments

The runtime places launch arguments in window.__args. Use values that belong to the app, such as an object or a display mode.

// launch another app with structured arguments
await window.__goldenbodyAPI.launchApp('notesApp', [
  { view: 'recent', id: 42 }
]);

// inside notesApp
const args = window.__args;
const view = args[0].view;

Opening a file immediately

When launched from File Explorer, the runtime provides window.userPickedFileHandle.


  // the handle is created even when no file is picked so check its path property
  if (window.userPickedFileHandle.path) {
  const result = await window.__goldenbodyAPI.readFile(
    window.userPickedFileHandle,
    { text: true }
  );
  const text = result.fileContent;
}

File access

An app can access files inside its app folder and shared files under /downloads. For files or folders elsewhere, use a picker and keep the returned handle and key.

Notifications

Notifications can be invoked by alert() only when the app has notification permission.

Admin apps

An app is only loaded with direct privileges when requestAdminPerm: true is paired with matching API keys from <app-folder>/jsKey.txt and /systemfiles/userprofile/jsApiKey.txt. Packages automatically receive the js api key during installation. Though the user will see a warning.

Launcher and instance tracking

window.myAdminAppGlobals = { instances: [] };

window.myAdminAppLauncher = function (posX = 50, posY = 50) {
  const appId = "myAdminApp";
  const pos = posX === 50 && posY === 50
    ? window.protectedGlobals.getNextWindowXY()
    : { x: posX, y: posY };

  const instance = window.protectedGlobals.apptools.api.createAppInstance({
    appId,
    posX: pos.x,
    posY: pos.y,
    width: 800,
    height: 520
  });

  window.protectedGlobals.apptools.api.trackInstance(instance, appId);

  const root = instance.rootElement;
  root.textContent = "Trusted app content";
};

createAppInstance creates the runtime window shell. trackInstance registers minimize, maximize, show, hide, close, and instance behavior.

Admin mode is for trusted system and developer apps that need direct runtime access. Normal apps should use the runtime API.

File system API

Normal apps call window.__goldenbodyAPI for file system operations. Also note that fs API can also return server errors.

Complete normal-app FS API

  • readFile(pathOrHandle, options) — read text, ArrayBuffer, stream, or direct content.
  • writeFile(pathOrHandle, content, options) — replace or append file content.
  • readFolder(pathOrHandle, options) — list a directory.
  • writeFolder(pathOrHandle, options) — create a directory.
  • fileExists(pathOrHandle, options) / folderExists(pathOrHandle, options) — test whether a file or folder exists.
  • deleteFile(pathOrHandle, options) / deleteFolder(pathOrHandle, options) — delete or permanently delete a target.
  • renameFile(pathOrHandle, newName, options) / renameFolder(pathOrHandle, newName, options) — rename a target.
  • pasteFile(destinationOrHandle, clipboard, options) / pasteFolder(destinationOrHandle, clipboard, options) — copy or move clipboard entries.
  • watchFile(pathOrHandle, callback, options) / watchFolder(pathOrHandle, callback, options) — observe file or folder changes.
  • closeWatch(watchId) / clearAllWatchers() — close one or all normal-app watchers.
  • showOpenFilePicker(options) — select an existing file and return an FShandle.
  • showSaveFilePicker(options) — choose a save destination and return an FShandle.
  • showDirectoryPicker(options) — select a directory and return an FShandle.

Reads and writes

const result = await window.__goldenbodyAPI.readFile('/demo/notes.txt', {
  text: true
});

await window.__goldenbodyAPI.writeFile('/demo/notes.txt',
  'updated text',
  { replace: true, text: true }
);

const entries = await window.__goldenbodyAPI.readFolder('/demo', {
  detail: true
});

Read options

  • { text: true } — String.
  • { buffer: true } — ArrayBuffer.
  • { stream: true } — ReadableStream.
  • { direct: true } — raw response value.

Write options

  • { replace: true } — replace the file; this is the default.
  • { replace: false } — append content.
  • { stream: true } — upload a supplied ReadableStream or Blob.
  • { retrytimeout: ms } — chunk retry timeout.

Handles

A picker handle is the permission record for a user-selected file or folder. Normal-app FS methods accept either a path or a handle. Keep a handle for later operations. It contains path, key, kind, and name.

const handle = await window.__goldenbodyAPI.showOpenFilePicker();
const result = await window.__goldenbodyAPI.readFile(handle, { text: true });
await window.__goldenbodyAPI.writeFile(handle, result.fileContent + '\nadded', {
  replace: true,
  text: true
});

Directory picker

const folder = await window.__goldenbodyAPI.showDirectoryPicker();
const child = {
  path: folder.path + '/notes.txt',
  key: folder.key
};
await window.__goldenbodyAPI.writeFile(child, 'hello', { text: true });

The folder handle itself is not a directory context. Append a child name to folder.path and reuse folder.key for each child operation.

Save picker

const destination = await window.__goldenbodyAPI.showSaveFilePicker({
  suggestedName: 'notes.txt'
});
await window.__goldenbodyAPI.writeFile(destination, 'Saved text', {
  replace: true,
  text: true
});

Other operations

await window.__goldenbodyAPI.writeFolder('/demo/new-folder');
await window.__goldenbodyAPI.renameFile('/demo/a.txt', 'b.txt');
await window.__goldenbodyAPI.renameFolder('/demo/new-folder', 'archive');
await window.__goldenbodyAPI.deleteFile('/demo/b.txt', { permanent: true });
await window.__goldenbodyAPI.deleteFolder('/demo/archive', { permanent: true });
await window.__goldenbodyAPI.pasteFile('/dest', { path: '/source/a.txt' });
await window.__goldenbodyAPI.pasteFolder('/dest', { path: '/source/folder' }, { move: true });

/downloads

/downloads is the shared application area. Normal apps can use paths beneath it for shared assets and inter-app data, not secrets.

Watchers

const watch = await window.__goldenbodyAPI.watchFile('./notes.txt', (event) => {
  if (!event || event.closed) return;
  console.log(event.changeType, event.path);
});
watch.close();

const folderWatch = await window.__goldenbodyAPI.watchFolder('/demo', (event) => {
  if (!event || event.closed) return;
  console.log(event.changeType, event.path);
});
folderWatch.close();

A watch can close for auth, rate-limit, network, or server reasons. Store and release stale watchers; do not assume automatic reconnection.

Windows and messages

Window controls

const bounds = await window.__goldenbodyAPI.getBounds();
window.__goldenbodyAPI.setBounds({ x: 120, y: 80, width: 900, height: 620 });
window.__goldenbodyAPI.setBounds({ maximize: true });
window.__goldenbodyAPI.setBounds({ minimize: true });
window.__goldenbodyAPI.setInstanceTitle('Document Editor');
window.__goldenbodyAPI.setTitlebarVisibility(false);
window.__goldenbodyAPI.setDragstripVisibility(true);
await window.__goldenbodyAPI.closeWindow(false); // false asks normally if askuserbeforeclose is true, see examples below

Close confirmation

await window.__goldenbodyAPI.setAskUserBeforeClose(true);
await window.__goldenbodyAPI.closeWindow(true); // force close

Inter-instance messages


// observer can use to observe theme changes and messages from other instances
const observer = window.__goldenbodyAPI.Observer((event) => {
  console.log(event.message);
}, 'message');

// this can normally be used to sync theme with default system theme
const themeObserver = window.__goldenbodyAPI.Observer((event) => {
  console.log(event.darkTheme); // true or false
}, 'theme');

await window.__goldenbodyAPI.message({ type: 'refresh' }, '*');
await window.__goldenbodyAPI.message({ type: 'save' }, 2);

// calling disconnect() stops the observer from receiving messages
observer.disconnect();
themeObserver.disconnect();

toInstance is an integer instance index, or * for broadcast. Use getCurInstanceNum(), and getLiveInstanceIndex() to identify instances.

Theme

const theme = await window.__goldenbodyAPI.getTheme(); // dark or light
window.__goldenbodyAPI.setTheme('auto');
window.__goldenbodyAPI.setTheme('dark');
window.__goldenbodyAPI.setTheme('light');

Launch another app


const apps = await window.__goldenbodyAPI.getAvailableAppsToLaunch();
await window.__goldenbodyAPI.launchApp('notesApp', [{ view: 'edit' }]);

Workers and terminal commands

Terminal commands

"cmd": [
  { "name": "workerTest", "src": "workerTest.js", "receive_onkill_handler": true },
  { "name": "doThing", "src": "doThing.js" }
]

Command names are normalized to lowercase [a-z]: spaces, numbers, and symbols are removed and uppercase letters are lowercased. For example, Worker-Test 2 becomes workertest. Names that contain no lowercase letters after normalization are skipped.

receive_onkill_handler enables graceful worker termination. When set to true, the runtime sends an onkill message before terminating the worker. The worker can handle it by defining self.onkill = function (event) { ... }; event.graceMs is 3000 (3 seconds).

The first kill request starts the 3-second grace period and sends onkill. Further kill requests show the remaining countdown and the third repeated kill request force-terminates the worker immediately. The runtime otherwise terminates it automatically after the grace period if it is still running.

Worker API

Terminal-worker FS methods accept path strings. Relative paths resolve from the worker's app folder. Except for /systemfiles, which they can only check existence or list entries, terminal workers can access files and folders throughout the virtual filesystem. Reads and mutations under /systemfiles are blocked; only directory listing and existence checks are available there.

  • api.cwd() — returns the terminal worker's current working directory.
  • api.readFile(path, options) — reads text, buffer, stream, or direct content from a path.
  • api.writeFile(path, content, options) — writes file content.
  • api.readFolder(path, options) — lists a directory.
  • api.writeFolder(path) — creates a directory.
  • api.fileExists(path) — reports whether a file exists.
  • api.folderExists(path) — reports whether a folder exists.
  • api.deleteFile(path, options) — deletes a file; options can request permanent deletion.
  • api.deleteFolder(path, options) — deletes a folder; options can request permanent deletion.
  • api.renameFile(path, newName) — renames a file.
  • api.renameFolder(path, newName) — renames a folder.
  • api.pasteFile(destination, clipboard) — copies a file entry at the destination.
  • api.pasteFolder(destination, clipboard) — copies a folder entry at the destination.
  • api.launchApp(appId, args) — launches another app with an arguments array.
  • api.watchFile(path, callback, options) — creates a file watcher and invokes the callback for watch events.
  • api.watchFolder(path, callback, options) — creates a folder watcher and invokes the callback for watch events.
  • api.closeWatch(watchId) — closes one watcher; it may also close through the watch object's close() method.
  • api.clearAllWatchers() — closes every watcher owned by the terminal worker.
  • api.setAskUserBeforeClose(value) — enables or disables confirmation before the terminal instance closes.
  • api.writeline(text, font, color, size) — creates a live terminal output line. Its returned handle supports update() and rewriteLine().
  • api.prompt(message, options) — opens an interactive terminal prompt and resolves to the entered text.
  • api.getStartArgs() — returns the worker's launch arguments object. self.args provides the same parsed arguments.

Prompt and live output

const text = await api.prompt('Edit file contents', {
  prefill: existingText,
  multiline: true
});

const status = await api.writeline('Working...', 'ui-monospace', '#3ddc97', 14);
status.update('Working... 50%');
status.rewriteLine('Finished', 'ui-monospace', '#3ddc97', 16);

Packaging and installation

Required ZIP layout

helloApp.zip
└── helloApp/
    ├── entry.json
    ├── script.js
    ├── icon.txt
    ├── styles.css
    └── assets/
        └── logo.png

The ZIP must contain exactly one top-level folder. That folder must contain entry.json and all app files. A ZIP with entry.json directly at its root will not install.

The installer expects the app files to be contained inside a single top-level folder. It locates entry.json inside that folder and installs the package contents into the app directory named from the entry id.

How installation works

  1. The installer validates JSON and requires a non-empty id.
  2. The package becomes /systemfiles/runtime/apps/<sanitized-id>.
  3. The installer creates folders and writes every archive file beneath that app folder.
  4. If requestAdminPerm is true, it writes jsKey.txt.
  5. The runtime validates the entry and loads the app.

Path rules

  • Use forward-slash relative paths in entry.json.
  • jsFile, iconFile, and command src are relative to the installed app folder.
  • Do not package absolute /systemfiles/runtime/apps paths inside source assets.

Installing and updating

Open App Installer and provide the ZIP path or launch it with ["/downloads/yourpackage.zip"]. Launching a package with an existing app id performs an update where the runtime already recognizes that app.

await window.__goldenbodyAPI.launchApp('App Installer', [
  '/downloads/helloApp.zip'
]);

Archive checklist

  • One valid entry.json in the package.
  • Every manifest path exists.
  • Admin packages include or receive a matching key before being trusted.

Permissions and app settings

Settings app permissions cover storage, notifications, and launching other apps:

  • storage — allow, deny, or ask before writes outside user-picked handles; reads do not require write permission.
  • notification — allow, deny, or ask before notification access.
  • launchApp — allow, deny, or ask before launching another app.

Read versus write

For user-picked content, use the returned handle and key for every read or write operation. Reads generally do not require the storage write permission, including reads from app-owned and shared locations. Normal apps require storage permission for write, delete, rename, folder creation, and paste operations when targeting paths outside user-picked handles; terminal workers can perform file operations without an app storage prompt.

Picker capability

When the user grants a file or folder through a picker, pass the returned handle and keep its key for later read or write operations.

Every operation on user-picked content uses the handle. Keep the handle and its key; do not replace it with a plain path.

Open with capability

The manifest's openfileCapability controls which file types File Explorer offers to the app. Examples:

"openfileCapability": [".txt", ".md"]
"openfileCapability": ["*"]

Admin trust

Verified admin apps are trusted developer apps with direct runtime access. Only include admin access when the app truly needs direct runtime control.

Troubleshooting

The app is missing from the start menu

  • Check that id, jsFile, and label exist and that JSON is valid.
  • If headless is true, an absent start-menu entry is expected.
  • Confirm iconFile exists for apps that appear in the interface.

Package installer says entry.json is missing

  • Place entry.json inside the ZIP, not beside a folder on the local desktop.
  • Confirm the file is named exactly entry.json, name matching is case-sensitive.

The admin app does not launch

  • Verify jsKey.txt exists in the app folder.
  • Verify it matches /systemfiles/userprofile/jsApiKey.txt.
  • Check functionName, globalVarObjectString, and allAppArrayString.
  • Ensure none of the identifiers collide with existing app identifiers.

A write fails

  • Use a path inside the app folder or under /downloads.
  • Check file and folder permissions.
  • For a picker handle, ensure the key is not lost between operations.
